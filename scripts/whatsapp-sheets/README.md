# חילוץ היסטוריית ווטסאפ לגוגל שיטס (Green API)

סקריפט Google Apps Script שמתחבר ל־WhatsApp דרך **Green API** ומחלץ את 100 ההודעות האחרונות
מאיש קשר או מקבוצה ישירות לגיליון.

גיליון היעד: **"חילוץ הסטוריית ווצאפ"**
`https://docs.google.com/spreadsheets/d/19pV44x9BU-fUVUJr13_poMCestdicupFx5jfLaON3Lg/edit`

## איך זה עובד

| עמודה | תוכן | מי ממלא |
|---|---|---|
| A | שם הקבוצה / איש הקשר | אתם |
| B | טלפון (לאיש קשר בלבד) | אתם |
| C | id של קבוצה | הסקריפט (או ידנית) |
| D | הסטוריה — קישור ללשונית ההודעות | הסקריפט |
| E | סטטוס | הסקריפט |
| F | עודכן | הסקריפט |

הלוגיקה בכל שורה:

1. אם עמודה **C** מלאה → מושכים לפי ה־id הזה (`<id>@g.us`).
2. אחרת, אם עמודה **B** מלאה → **איש קשר**: המספר מנורמל (`054-484-4035` → `972544844035`)
   וה־chatId הוא `972544844035@c.us`.
3. אחרת → **קבוצה**: מחפשים בלשונית "קבוצות" קבוצה שהשם שלה תואם לעמודה A,
   כותבים את ה־id שלה לעמודה C, ומושכים לפי `<id>@g.us`.

ההודעות נכתבות ללשונית נפרדת לכל שיחה בשם `שיחה · <שם>`, עם העמודות:
מספר סידורי, תאריך ושעה, כיוון (נכנסת/יוצאת), שם השולח, מספר השולח, סוג ההודעה,
טקסט, קובץ/מדיה, ומזהה ההודעה. בעמודה D בגיליון הראשי נוצר קישור ללשונית הזו.

## התקנה

1. פותחים את הגיליון → **תוספים (Extensions) ← Apps Script**.
2. מוחקים את התוכן של `Code.gs` ומדביקים את כל התוכן של
   [`Code.gs`](./Code.gs) מהתיקייה הזו.
3. אופציונלי: בגלגל השיניים ← **Show "appsscript.json" manifest file**, ומדביקים את
   [`appsscript.json`](./appsscript.json).
4. שומרים (💾), וחוזרים לגיליון ומרעננים את הדף (F5).
5. בתפריט העליון מופיע תפריט חדש: **ווטסאפ**.

## הגדרה ראשונה

1. **ווטסאפ ← 1. הגדרת Green API** — מדביקים `idInstance` ו־`apiTokenInstance`
   מהאזור האישי של Green API (console.green-api.com), ובוחרים כמות הודעות (ברירת מחדל 100).
   בפעם הראשונה גוגל תבקש אישור הרשאות — מאשרים.
2. **ווטסאפ ← 2. בדיקת חיבור** — אמור להחזיר `authorized`.
   אם לא, סורקים מחדש את ה־QR באזור האישי של Green API.
3. **ווטסאפ ← 3. רענון רשימת הקבוצות** — מושך את כל הקבוצות שהמספר שלכם חבר בהן
   ושומר אותן בלשונית "קבוצות" (שם + id). זה מה שמאפשר לחפש קבוצה לפי שם.

המפתחות נשמרים ב־`DocumentProperties` של הגיליון — לא בתאים, ולא בקוד.

## שימוש

- **ווטסאפ ← משיכת היסטוריה — השורה הנוכחית** — מריץ רק על השורה שהסמן עליה.
- **ווטסאפ ← משיכת היסטוריה — כל השורות** — מריץ על כל השורות מ־2 ומטה.

בין שורה לשורה יש השהיה של 1.2 שניות כדי לא לחרוג ממכסת הקריאות של Green API.
כל הרצה נרשמת בלשונית "לוג" (זמן, רמה, יעד, chatId, פירוט).

## נקודות חשובות

- **`getChatHistory` מחזיר רק הודעות שנשמרו במאגר של Green API** מרגע שהמופע חובר.
  היסטוריה ישנה מלפני החיבור לרוב לא תחזור — זו מגבלה של Green API, לא של הסקריפט.
- **כתובת ה־API** נגזרת אוטומטית מה־idInstance (`https://<4 ספרות ראשונות>.api.greenapi.com`).
  אם באזור האישי מופיעה כתובת אחרת, אפשר לדרוס אותה ב־Apps Script:
  **Project Settings ← Script properties**, מפתח `GREENAPI_API_URL`.
- **קידומת מדינה** ברירת מחדל `972`. לשינוי: script property `GREENAPI_COUNTRY_CODE`.
- אם שם הקבוצה מתאים לכמה קבוצות, הסקריפט עוצר ומבקש לדייק את השם או להזין id ידנית
  בעמודה C (אפשר להעתיק אותו מלשונית "קבוצות").
- מכסת Green API בתוכנית החינמית מוגבלת; משיכה של הרבה שורות ברצף עלולה להחזיר 429.

## הרצה אוטומטית (אופציונלי)

ב־Apps Script ← **Triggers ← Add Trigger**:
פונקציה `extractAllRows`, מקור `Time-driven`, למשל כל יום בשעה קבועה.
שימו לב ש־`extractAllRows` מציג חלונית סיכום בסוף — בהרצת טריגר היא פשוט לא מוצגת.

# לשונית "אנשי קשר"

נבנית ומתעדכנת אוטומטית אחרי כל חילוץ היסטוריה. כל מי ששלח הודעה נכנסת
נרשם שם — גם מקבוצות וגם משיחות פרטיות.

| עמודה | תוכן |
|---|---|
| A | מזהה — הטלפון המנורמל. זה מפתח הכפילויות |
| B | שם |
| C | שמות נוספים — אותו אדם עם שם אחר בקבוצה אחרת |
| D | טלפון |
| E | סוג — איש קשר / משתתף בקבוצה / שניהם |
| F | מקורות — `Daily - Galiluz (42) \| רוני (100)` |
| G | סה״כ הודעות |
| H–I | הודעה ראשונה ואחרונה |
| J | סיכום AI |
| K | עודכן סיכום |
| L | **הערות ידניות — הקוד לא נוגע בעמודה הזו אף פעם** |
| M | יומן שינויים — נצבר, החדש למעלה |

## כללי המיזוג

- **בלי כפילויות.** המפתח הוא הטלפון המנורמל, כך שאותו אדם בשלוש קבוצות
  הוא שורה אחת.
- **בלי דריסה.** שורות לא נמחקות ולא מנוקות. `שם` נכתב רק אם התא ריק;
  שם אחר שמתגלה נצבר ל`שמות נוספים`.
- **חילוץ חוזר לא מכפיל.** `מקורות` שומר ספירה נפרדת לכל שיחה, וחילוץ
  מחדש של אותה שיחה מעדכן את הערך שלה במקום להוסיף עוד אחד.
- **טווח התאריכים מתרחב בלבד**, אף פעם לא מצטמצם.
- **הסיכום וההערות שורדים** כל חילוץ עתידי.

## שמות לשוניות השיחה

`שיחה · Daily - Galiluz [120363043968967975]` — התווית לקריאוּת, ה-chatId
לייחודיוּת.

בלי הסיומת השם נגזר מהתווית בלבד, ותוויות אינן ייחודיות: שתי שורות באותו
שם — אחת קבוצה ואחת איש קשר — היו כותבות לאותה לשונית ומערבבות שתי שיחות
לארכיון אחד. גם החיטוי יצר התנגשויות (`פרויקט A/B` ו-`פרויקט A B`).

לשוניות שנוצרו לפני השינוי מקבלות שם חדש אוטומטית, לפי ה-chatId שכבר
שמור בתא B2 שלהן. שינוי שם משמר את כל הנתונים ואת הקישורים בעמודה
"הסטוריה", כי הם מצביעים ל-gid ולא לשם. ההגירה בטוחה להרצה חוזרת, ורצה
לבד בתחילת חילוץ, דירוג וסנכרון.

אם שם היעד כבר תפוס, ההגירה **לא דורסת** — זו התנגשות אמיתית שקרתה בעבר,
ומיזוג אוטומטי עלול לאבד נתונים. היא נרשמת בלשונית `לוג`.

## לשוניות השיחה הן ארכיון

Green API מחזיר רק את ההודעות האחרונות, אז חילוץ חוזר בעוד חודשיים מביא
חלון אחר לגמרי. לכן לשונית השיחה **לא נמחקת ונכתבת מחדש** — היא ממוזגת:

- הודעות קיימות נשארות, חדשות נוספות
- כפילויות מזוהות לפי `idMessage`
- הכל ממוין כרונולוגית
- הספירה ב"מקורות" משקפת את הארכיון המלא, לא את המשיכה האחרונה

בלי זה, הודעות ישנות היו נעלמות — וביחד איתן הראיות שהסיכום נבנה מהן.
המחיר: הלשוניות גדלות עם הזמן. זו הכוונה.

## מה קורה בסיכום חוזר

הסיכום מקבל את **הכרטיס הקודם** כידע קיים, לא מתחיל מאפס. ההנחיה למודל:
לשמור כל עובדה מהכרטיס הישן שהחומר החדש אינו סותר — גם בלי ראיה תומכת
הפעם — להוסיף את החדש, ואם יש סתירה להעדיף את החדש ולציין מה השתנה.

כך שאם אותו אדם כתב בקבוצה בינואר ובפרטי במרץ, הכרטיס יכיל את שניהם.

## מעקב שינויים

המודל מחזיר שני חלקים מופרדים: הכרטיס המעודכן, וההפרש מול הכרטיס הקודם.
הכרטיס נכתב לעמודה J, וההפרש **נוסף** לעמודה M מעל הרשומות הקודמות —
כך שנוצר ציר זמן ולא רק תמונת מצב.

בחלק השינויים המודל עובר אחד-אחד על הפריטים שהיו תחת "פתוח מולו" בכרטיס
הקודם וקובע מה קרה לכל אחד. פריט שנסגר **יוצא מהכרטיס** ונרשם ביומן:

```
── 22/09/2026 10:04 ──
[הושלם] העלאת הפרק לדרייב — כתבה "מעלה לדרייב" ב-01/03
[התקדם] המיקס הסתיים, נשאר אישור סופי
[חדש] עובדת מהסטודיו בכרמיאל
[השתנה] מיקום: היה תל אביב, עכשיו כרמיאל
```

הרצה שבה שום דבר לא השתנה לא מוסיפה רשומה ריקה ליומן. אם המפריד חסר
בפלט מסיבה כלשהי, כל הפלט נחשב לכרטיס — עדיף כרטיס בלי יומן מאשר כלום.

## סיכום AI

דורש מפתח OpenAI: **ווטסאפ ← הגדרת מפתח OpenAI**. מודל ברירת מחדל
`gpt-4o-mini`, בהתאם למה שכבר בשימוש בפרויקט.

**ווטסאפ ← סיכום AI לאנשי קשר** מסכם רק את מי שאין לו סיכום, או שהגיעו
ממנו הודעות חדשות מאז הסיכום האחרון. **סיכום AI — רענון מלא** מייצר מחדש
להכל (מחליף סיכומים קיימים; הערות ידניות לא נפגעות).

הסיכום נבנה משתי קבוצות ראיות שנאספות מכל לשוניות השיחה:
מה שהאדם כתב, ומה שאחרים כתבו עליו. המודל מקבל הוראה מפורשת לא להשלים
פרטים מהידע הכללי שלו ולסמן מסקנות משוערות — כרטיס קצר ונכון עדיף על
כרטיס מלא ומנוחש.

מגבלות ריצה: עד 25 אנשי קשר להרצה ועד 4.5 דקות, בגלל תקרת זמן הריצה של
Apps Script. אם נשארו — פשוט מריצים שוב, זה ממשיך מהמקום שנעצר.

## שימו לב

הלשונית הזו בונה פרופילים על אנשים אמיתיים מתוך הודעות פרטיות, ושולחת את
ההודעות שלהם ל-OpenAI לצורך הסיכום. שווה להחזיק את זה בראש כשמחליטים אילו
שיחות לחלץ ועם מי לשתף את הגיליון.

# כפתור ההוספה בלשונית הקבוצות

בלשונית **קבוצות** יש עמודה **"הוסף לחילוץ"** עם תיבת סימון בכל שורה.
לוחצים — הקבוצה נוספת לגיליון הראשי, הסימון מתנקה מעצמו, ובעמודה
**"סטטוס"** נרשם לאן היא נוספה.

| עמודה | תוכן |
|---|---|
| A–C | שם, id, chatId |
| D–E | ציון רלוונטיות ופירוט |
| F | **הוסף לחילוץ** — תיבת הסימון |
| G | סטטוס |

השורה שנוספת לגיליון הראשי מקבלת את השם בעמודה A ואת ה-id בעמודה C,
**ועמודת הטלפון נשארת ריקה בכוונה** — כך היעד מזוהה כקבוצה ולא כאיש קשר.

לחיצה חוזרת על קבוצה שכבר בגיליון לא יוצרת כפילות; הסטטוס פשוט אומר
באיזו שורה היא כבר נמצאת.

## למה תיבת סימון ולא כפתור

Apps Script לא יכול למקם כפתור בתוך תא. כפתורי ציור הם אובייקטים צפים —
אחד לגיליון, לא אחד לשורה. תיבת סימון עם טריגר `onEdit` נותנת את אותה
חוויה של לחיצה אחת, ועובדת גם בנייד.

הטריגר הוא טריגר פשוט: הוא רץ בלי אישור הרשאות נפרד ומוגבל ל-30 שניות,
ולכן הוא עושה רק פעולות גיליון ולא נוגע ב-API חיצוני.

## גיבוי מהתפריט

`onEdit` לא נורה כשמסמנים דרך API או כשהטריגר חסום. לכן יש גם
**ווטסאפ ← הוספת הקבוצות המסומנות לחילוץ**, שמטפלת בכל המסומנות בבת אחת.
שימושי גם כשרוצים לסמן כמה ואז להוסיף יחד.

## מיון

הדירוג ממיין את לשונית הקבוצות על פני כל שבע העמודות, כך שתיבת הסימון
והסטטוס נעים עם השורה שלהם. אחרת כל סטטוס היה מתייחס לקבוצה אחרת.

# דירוג רלוונטיות

**ווטסאפ ← עדכון דירוג רלוונטיות** מחשב ציון לכל איש קשר, שיחה וקבוצה,
כותב אותו לשתי עמודות בסוף כל לשונית, וממיין מהגבוה לנמוך.

## למה לא פשוט למיין לפי כמות הודעות

כי זה מטעה. קבוצה רועשת שלא נגעת בה חודש תעקוף לקוח שכתב לך אתמול.
לכן הציון משקלל חמישה אותות:

| אות | משקל | על מה הוא עונה |
|---|---|---|
| טריות | 35% | מתי דיברתם לאחרונה. דעיכה מעריכית, חצי חיים ~10 ימים |
| נפח | 25% | כמה הודעות בחודש. לוגריתמי, כדי שקבוצה ענקית לא תמחק את השאר |
| עקביות | 20% | בכמה ימים **שונים** הייתה פעילות |
| מעורבות | 10% | בשיחה: כמה אתה כותב שם. באיש קשר: בכמה שיחות הוא פעיל |
| מגמה | 10% | 30 הימים האחרונים מול ה-30 שלפניהם |

**עקביות** היא האות שהכי קל לפספס: עשרים הודעות על פני עשרה ימים הן קשר
חי, עשרים בפרץ אחד הן אירוע חד-פעמי. בלי זה, כל ויכוח בקבוצה היה מזנק
לראש הרשימה.

**מעורבות** מבדילה בין קשר לצפייה — קבוצה שאתה רק קורא בה שווה פחות
מקבוצה שאתה כותב בה.

## עמודת הפירוט

```
32 הודעות · 24 ימים פעילים · היום · עולה
40 הודעות · 5 ימים פעילים · לפני 25 ימים · דועך
```

התווית האחרונה לא נגזרת רק מיחס החלונות: פעילות שכולה ישנה מסומנת
כדועכת גם כשאין לה עבר, כי ארבעים הודעות מלפני 25 יום אינן "חדש".

## המיון

מתבצע דרך `Range.sort` המובנה ולא דרך כתיבת ערכים, כך שקישורים, תאריכים
ועיצוב נעים עם השורה במקום להישרף. ההערות הידניות והיומן נעים עם השורה
שלהם.

לשוניות שאין להן ארכיון שיחה מקבלות ציון 0 ויורדות לתחתית.

## חי מווטסאפ מול מהגיליון

בתפריט יש שתי פעולות, והן לא אותו דבר:

| | מקור הנתונים | מה רואים |
|---|---|---|
| **סנכרון פעילות מווטסאפ (חי)** | Green API | **כל** השיחות בווטסאפ המחובר, גם כאלה שמעולם לא חילצת |
| **דירוג לפי הגיליון בלבד** | לשוניות השיחה | רק מה שכבר חילצת. עובד בלי קריאות API |

הסנכרון החי מושך את יומן ההודעות של כל השיחות בשתי קריאות
(`lastIncomingMessages` + `lastOutgoingMessages`) ואת רשימת הצ׳אטים
בקריאה שלישית, ובונה מהן לשונית **"כל השיחות"** ממוינת לפי ציון.

הסנכרון מעדכן ארבע לשוניות בהרצה אחת:

- **כל השיחות** — **שיחות פרטיות בלבד**, ממוינות לפי ציון. קבוצות לא
  מופיעות כאן: יש להן לשונית משלהן עם אותם ציונים, ובאותה טבלה הן היו
  מציפות את אנשי הקשר בלי להוסיף מידע.
  `getContacts` מחזיר גם אנשי קשר מהפנקס שמעולם לא התכתבתם איתם — שורות
  בציון אפס אינן "שיחות" והן מושמטות, אלא אם הן כבר יעד חילוץ בגיליון
  הראשי. ההודעה בסוף הריצה אומרת כמה הושמטו.
- **אנשי קשר** — ציונים ומיון מהנתונים החיים, כך שגם מי שמעולם לא חילצת
  את השיחה איתו מקבל ציון אמיתי
- **קבוצות** — קבוצות חדשות מווטסאפ נוספות לרשימה (שורות קיימות נשארות,
  ייתכן שהוזן בהן id ידנית), ואז ציון ומיון
- **הגיליון הראשי** — ציון ומיון. שורת קבוצה נפתרת לפי ה-id, שורת איש
  קשר לפי המספר המנורמל

### מגבלת היומן

Green API שומר את יומן ההודעות לתקופה מוגבלת, שתלויה גם בתוכנית. אם
ביקשתם 30 יום וקיבלתם פחות, ההודעה בסוף הריצה אומרת כמה ימים היומן כיסה
בפועל — זו מגבלה של Green API ולא באג. המגמה מחושבת בתוך מה שהתקבל
(חצי מאוחר מול חצי מוקדם), כדי שחלון קצר מהצפוי לא ייתן מגמה חסרת משמעות.

לשינוי החלון: **ווטסאפ ← הגדרת חלון הפעילות**.

# תחזוקה דרך clasp (במקום הדבקה ידנית)

`clasp` הוא ה-CLI הרשמי של גוגל ל-Apps Script. אחרי הקמה חד-פעמית אפשר לערוך את
`Code.gs` כאן בריפו ולדחוף לגיליון בפקודה אחת — בלי העתק-הדבק.

## הקמה חד-פעמית

### 1. להדליק את ה-API

להיכנס ל־https://script.google.com/home/usersettings (עם החשבון שבעלים של הגיליון)
ולהדליק **Google Apps Script API**. בלי זה clasp מקבל 403.

### 2. להתקין clasp

```bash
npm install -g @google/clasp
clasp --version          # צריך 3.x
```

דורש Node 18 ומעלה.

### 3. להתחבר

```bash
clasp login              # נפתח דפדפן, בוחרים את החשבון ומאשרים
clasp show-authorized-user
```

ההרשאה נשמרת ב־`~/.clasprc.json` ושורדת בין סשנים. הקובץ הזה הוא סוד —
הוא כבר ב־`.gitignore`, לא להעתיק אותו לריפו ולא לשלוח אותו לאף אחד.

### 4. לקשר את הפרויקט

מריצים **מתוך `scripts/whatsapp-sheets/`**:

```bash
cd scripts/whatsapp-sheets
```

**אם עדיין לא הדבקתם את הקוד ב-Apps Script** — יוצרים פרויקט מקושר לגיליון:

```bash
clasp create --title "חילוץ הסטוריית ווצאפ" \
  --parentId 19pV44x9BU-fUVUJr13_poMCestdicupFx5jfLaON3Lg
```

**אם כבר הדבקתם** — לוקחים את ה-Script ID מ-Apps Script ←
`Project Settings` ← `Script ID`, ומריצים:

```bash
clasp clone <SCRIPT_ID>
git checkout Code.gs appsscript.json   # מחזירים את הגרסה שבריפו
```

שתי הדרכים יוצרות `.clasp.json` עם ה-Script ID. הקובץ הזה אינו סוד וכדאי לקמט אותו.

### 5. לדחוף

```bash
clasp show-file-status   # מראה מה יידחף
clasp push
clasp open-script        # פותח את ה-IDE לבדיקה
```

## שגרת עבודה

```bash
clasp pull    # לפני עריכה, אם נגעתם בקוד דרך הדפדפן
# ... עורכים את Code.gs ...
clasp push    # דוחפים לגיליון
```

**`clasp push` דורס את הגרסה המרוחקת.** אם ערכתם ב-IDE של Apps Script ולא עשיתם
`pull` — העריכה הזו תימחק. יש היסטוריית גרסאות ב-Apps Script אם צריך לשחזר.

`.claspignore` בתיקייה מגביל את הדחיפה ל־`Code.gs` ו־`appsscript.json` בלבד,
כך ש-`README.md` לא נדחף לפרויקט.
